# M Taufik Baskoro Portfolio

An editorial portfolio built with Next.js 16, React 19, and TypeScript. The restrained broadsheet direction uses ink-and-paper tokens, asymmetric project composition, illustrative CSS artifacts, and long-form feature routes.

## Routes

- `/` - front-page portfolio
- `/work/[slug]` - statically generated project stories
- `/design-system` - live internal design reference (`noindex`)

The authored projects cover Astra JM, Quantum Rekatama, and Dapodikdasmen Kota Medan.

## Development

```bash
npm install
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Open http://localhost:3000.

Run lint and the production build:

```bash
npm run lint
npm run build
```

If Turbopack cannot spawn its CSS worker in a restricted environment, use the supported Webpack build path:

```bash
next build --webpack
```

## Source of truth

Profile, contact details, skills, background, credentials, project stories, and
GitHub curation live in MySQL. Prisma queries shape the existing UI contracts;
the authored TypeScript and JSON files remain as inputs to the idempotent seed
until the production database has been verified.

The three project stories use supplied CV facts only. Unsupported dates, roles, testimonials, and outcome metrics are omitted. Project artwork is illustrative CSS, not a product screenshot. The public phone number is intentionally omitted.

Contact routes are `mtaufikbaskoro@gmail.com`, LinkedIn, and GitHub.

Set `DATABASE_URL` from `.env.example`, then run the database commands listed
above. See [database operations](docs/database.md) for migrations, content
updates, and backup/restore procedures.

## GitHub showcase

The public account and account type come from the `Profile` record. The
integration is read-only and uses the user repositories endpoint for a personal
account or the organization endpoint for an organization.

```bash
cp .env.example .env
```

`GITHUB_TOKEN` is optional and server-only. A read-only token raises the API rate limit. Do not add a `NEXT_PUBLIC_` prefix or commit a real token.

Featured repositories, their order, labels, description overrides, visibility,
and approved homepage hosts are database records. Only repositories in this
explicit allowlist render. Empty repositories, forks, archived repositories,
disabled repositories, and private repositories are excluded.

Repository facts are cached for the `hours` Next.js cache profile under the
`github-showcase` tag. A successful response is normalized and stored in MySQL
in one transaction before it reaches the UI. If GitHub cannot be reached or
returns malformed data, the latest stored snapshot is used. If both the live
response and stored snapshot contain no allowlisted repositories, the section
is omitted.

`data/github-showcase-fallback.json` only seeds the initial snapshot for a new
database. Live requests subsequently refresh snapshots in MySQL. Never include
tokens, private data, or raw API payloads in a snapshot. A saved-snapshot note
appears after seven days of fallback age.
